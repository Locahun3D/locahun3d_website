Blenderで3DGSを使うなら？ 描画品質・処理時間・動画で比較

全景データを使い、静止画・処理負荷・360度動画の3つのケースで検証します。

  1. 検証の目的
  2. 結論：構成ごとの結果を比較し、製品の総合順位は保留
  3. 比較対象とテスト環境
  4. CASE 01｜同じ画角で静止画を比較
  5. CASE 02｜全1,720万点の処理時間とメモリ
  6. CASE 03｜360度動画で動いたときの品質を確認
  7. 検証を終えて：導入前に確認すること

01 検証の目的

ロケハン3Dの中村です。
渋谷スクランブル交差点の3DGSをBlenderで読み込み、映像の背景として出力します。
今回は「読み込めたか」だけでなく、実際の画・待ち時間・動いたときの見え方を確認します。
全景を残した同じデータを使い、静止画、処理負荷、360度動画の3つに分けて検証しました。

02 結論：構成ごとの結果を比較し、製品の総合順位は保留

現時点では方式の優劣を確定しません。静止画と測定結果は下記の条件で確認済みですが、内部の色処理・背景・保持データに差があります。
全4条件の動画と、表示設定をそろえた4方向の静止画を追加しました。内部の色処理・保持データ・ローカル修正は異なるため、以下は明示した構成同士の比較であり、配布版製品の総合順位ではありません。

03 比較対象とテスト環境

CPUIntel Core Ultra 9 285K
GPURTX 5090 / 32 GB / driver 610.47
RAM / Blender64 GB / Blender 5.1.2
データShibuya / 17,201,445 splats / SH0 PLY
カメラ(-10, -22, 0.2) / 24 mm / 1280 × 720
描画方式KIRI: dedicated GPU / BlendSplat & SplatBake: EEVEE
検証版KIRI 5.1.0 + local patch / BlendSplat b980818 + local library edits / SplatBake 1.20.16

方式ごとに別プロセスで順番に実行し、同じカメラの静止画を3回出力しました。
入力の切り出し・間引きはしていません。画質設定は方式ごとに異なるため、同一画質に調整した速度競争ではありません。
BlendSplatはAgX、SplatBakeはStandardの保存シーンの色設定を使用します。専用レンダラーとの色味の差も画像に含まれます。

04 CASE 01｜同じ画角で静止画を比較

設定のポイント

KIRIは全点を保持するProxyで専用描画します。BlendSplatは64と512サンプル、SplatBakeはBake DiscsとEEVEEの64サンプルです。
カメラは交差点中央に固定しました。各画像を開くと同じ1280×720で確認できます。

レンダリング結果

検証結果

BlendSplatの64と512では、特に路面や建物の面で粒状感の違いを確認します。サンプル数を増やしても、スキャンにない形状を復元できるわけではありません。
KIRIの画像も、ガラスや人の残像、取得できていない領域の欠けが残ります。静止画が出力できたことと、映像全体に問題がないことは分けて判断します。

今回の画像では、BlendSplat 512は64よりも看板周辺や建物表面の細かい粒が目立ちにくくなりました。KIRIは看板文字や窓枠が明瞭な一方、人の残像や黒い欠損領域は残っています。SplatBake 64は短時間で出力できましたが、建物表面の粒状感が見られます。

比較時に区別する点

KIRIの90度画像の背景を画素確認するとRGBA=(0,0,0,0)で、透明でした。同じ位置のBlendSplat・SplatBakeは不透明な灰色です。黒い背景と灰色の背景の違いを、描画品質の優劣として数えません。
表示設定をそろえても内部の色処理や背景合成は異なります。Standard画像は以下で同じ灰色の下地に表示しますが、レンダリング手法そのものを統一した比較ではありません。

色設定をそろえた4方向

4条件ともStandard・露出0・ガンマ1・sRGB表示に設定し、同じカメラで0／90／180／270度を描画しました。これは表示設定をそろえるテストです。内部の色変換や合成方式まで同じになるわけではありません。

05 CASE 02｜全1,720万点の処理時間とメモリ

設定のポイント

同じ静止画を3回レンダーし、呼び出しからPNG保存完了までを測定しました。保存シーンの読み込み時間はこの表に含めません。初回は初期化やシェーダー準備を含みます。

測定結果

方式初回 秒3回の中央値 秒最大RAM GiB
KIRI 5.1.0 / local patch15.33711.60527.66
BlendSplat / EEVEE 6412.91911.98222.74
BlendSplat / EEVEE 51221.21119.96619.90
SplatBake 1.20.16 / EEVEE 646.8144.65113.27

検証結果

グラフは小さいほど短時間・省メモリです。サンプル数と出力画像を合わせて確認してください。
RAMは2秒間隔で取得したプロセス使用量の最大値です。方式によって保持する編集データが違い、KIRIは描画専用Proxy構成です。製品そのもののメモリ効率順位とは扱いません。

この条件で最短だったのはSplatBakeの中央値4.65秒です。BlendSplatは64から512へ増やすと約1.67倍の時間になりました。KIRIの静止画は約11.60秒で、今回の静止画速度では最速ではありません。この結果だけで画質を含む総合順位は決められません。

06 CASE 03｜360度動画で動いたときの品質を確認

設定のポイント

4条件とも全景データ・同じカメラ位置・24mm・1280×720・24fps・240枚で、その場を360度見回します。
動画は各シーンの従来の色設定で、AI補修やフレーム補間はありません。色設定をそろえた比較はCASE 01のStandard画像を使用します。

レンダリング結果

処理時間

KIRIは平均7.752秒／枚・合計1865.48秒。BlendSplat 512は平均18.373秒／枚・合計4409.57秒。SplatBakeは平均4.437秒／枚・合計1064.94秒でした。
BlendSplat 64の既存動画は分割実行のため、今回と同じ測定範囲の総時間を記載しません。異なる時点の実行であり、同一画質の速度ランキングではありません。

検証結果の読み方

4条件とも全240枚を出力できました。ただし、完走は「ちらつきなし」を意味しません。窓枠、看板、路面の変化を同じ方向で比較してください。
512サンプルで静止画の粒が減っても、形状の欠けや動く人の残像は残ります。黒い背景と灰色の背景の違いも画質点数に含めません。
UE5との同条件比較や、知覚品質をそろえた速度評価は未実施です。24fpsは再生速度で、操作中のFPSではありません。

07 検証を終えて：導入前に確認すること

KIRI、BlendSplat、SplatBakeの動画・静止画を比較できます。ただし、配布版そのままの総合推奨は行いません。
大容量の全景では、読み込み成功だけでなく、出力まで通るか・必要な画角が破綻しないかを確認してください。

今回のKIRIはGPU転送と索引精度を修正した隔離実行です。配布版アドオンは変更していません。一般的な編集や変形用の手順ではありません。

今回の比較に含めていない候補

ReshotAI、Fast Splatting、Octane、Splat Forge、Splat-enabled Blenderは全景・同条件の比較未完了です。3DGS Painterや生成・学習ツールは目的が異なるため、この描画比較とは分けます。未実施のものに推測の点数は付けません。

AIによる映像の仕上げは、UE5・XGRIDs・AIの検証記事をご覧ください。
